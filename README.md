# みーつけた

子どもがおにになって、どうぶつたちを探すWebアプリです。

**[あそぶ](https://ishiishikou.github.io/mi-tsuketa/)** · [ロードマップ #1](https://github.com/ishiishikou/mi-tsuketa/issues/1) · [iPhone確認手順](docs/iphone-acceptance.md)

## あそび方

1. 明るい場所で「あそぶ」を押して、フロントカメラを許可します。顔を映して数秒待ちます。
2. うさちゃん・くまちゃん・ねこちゃんから選びます。
3. 目を閉じるとカウントが進みます。途中で開けると「今見てた？」と反応し、約1.6秒間だけ、その瞬間の顔が出ます。
4. 閉じ直すと**残り時間から**続けられます。顔が外れた場合もそれまでの時間は失われません。
5. 目標に達してから目を開けると、木・家・花のどこに隠れたかを探せます。
6. 見つけて「つぎも あそぶ！」を押すと、目標は10 → 15 → 20 → 30 → 45 → 60秒と延びます。以降は60秒です。

音や振動は使いません。達成後も閉眼が続く間は静かに待ち、さらに約60秒間の閉眼を確認できたらカメラを停止します。睡眠を医学的に判定する機能ではありません。

21:00〜翌6:00はキャラクターが寝ています。昼間の暗所では「暗いから」と伝えます。開始後の明るさの変化ではゲームを止めません。タブ切替・画面ロック・カメラ中断ではカメラを解放し、「カメラを さいかい」で残り時間から戻れます。ページの再読み込みやブラウザ終了ではラウンドは保存されません。

## ホーム画面・オフライン

Safariの共有 →「ホーム画面に追加」で起動できます。初回はオンラインで開き、「おうちの方へ」にある**オフラインの準備ができました。**を確認してください。非対応ブラウザ・初回の準備中・準備失敗・更新失敗・更新待機はそれぞれ別の案内を表示します。初回インストールが失敗した場合は接続して開き直してください。

アプリ・MediaPipe・WASM・モデルを同じ配信元から取得し、Service Workerでまとめてキャッシュします。全資材の取得が成功した版だけが利用可能になります。更新は遊んでいる途中に強制適用せず、**開いているこのアプリのタブとホーム画面のすべてを閉じて**開き直したときに切り替えます。新版がwaitingなら新しい版の準備ができたと表示します。更新に失敗しても以前の版は使えます。更新エラーのあとに表示される準備完了通知で、更新失敗やwaitingの案内を上書きしません。Safariがキャッシュを削除した場合や、まだ準備できていない初回のオフライン起動には通信が必要です。

iPhone実機でのホーム画面起動・オフライン利用・新しい判定の使い心地は [#13](https://github.com/ishiishikou/mi-tsuketa/issues/13) の確認対象です。ブラウザ自動試験はiPhone実機での精度保証ではありません。

## プライバシー

- カメラは映像のみを使い、マイクを要求しません。
- 顔・目・明るさの判定は端末内で行います。サーバー/API/DB/解析サービスはありません。
- 開眼時の画像は小さいcanvasの画素として一時表示するだけです。画像ファイル化、localStorage、IndexedDB、キャッシュへの画像保存はしません。
- 表示終了・顔喪失・タブ非表示・終了・次ラウンドでcanvasの画素を消去します。明るさ測定用canvasも毎回消去します。
- カメラフレーム・ランドマーク・目の値をネットワークへ送信せず、ログにも残しません。
- 通信はアプリと固定モデル等のGET取得だけです。CSPで外部接続も制限しています。
- 公開リポジトリ/テスト成果物に、実際の子どもの写真・動画は含めません。ブラウザ試験は図形だけの合成カメラを使います。
- 配信元GitHub Pagesが通常のアクセス情報を扱うことは、アプリによるカメラデータ送信とは別です。

## 判定・構成

`game-core.mjs` はカメラやDOMから独立した状態機械です。`sensing.mjs` は両眼の継続判定・暗さ・端末時刻、`characters.mjs` は状態別のセリフと動作、`app.js` はカメラのライフサイクル・canvas・UIを担当します。

- 約250msごとに推論。両眼のスコアが閉眼0.55以上で500ms、開眼0.25以下で750ms続くと確定。
- 生の目の値が不明/開眼候補になった時点で加算を止めます。開眼確定時だけリアクション。
- 新しい2つの有効な閉眼サンプルの間だけを加算。750msを超える間隔は丸ごと捨て、動画停止・バックグラウンド・処理遅延を閉眼時間としません。
- 顔なしは即時計測停止、1秒継続でメッセージ。復帰のリアクション中も停止します。
- 暗さは顔の周囲を除いた背景の輝度中央値（閾値45）。500ms間隔、2.5秒以上の複数サンプルで判定し、ゲーム開始時に測定を止めます。
- 「おうちの方へ → 判定の調整・確認」で閾値をそのセッションだけ調整できます。値は実機調整前の暫定値です。

## 開発・テスト

Node.js 22以降:

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run build
npx playwright install --with-deps chromium webkit
npm run test:browser
npm run serve
```

`http://127.0.0.1:4173/mi-tsuketa/` を開きます。カメラはHTTPSまたはlocalhostで利用します。ビルド時に固定版のモデルを取得しSHA-256を検証します。`dist/` だけをGitHub Pagesに配信し、テスト・依存パッケージ・作業ファイルは配信しません。

テストは時間計測/判定とPWAの状態通知の単体試験、Chromium/WebKitの合成カメラによる通し操作、Chromiumで実MediaPipeの読込とオフライン再読込を確認します。加えて、本番と同じService WorkerテンプレートでA/B配信を切り替え、更新waiting中の旧版保持、全タブ終了後の切替、更新資材404から旧版オフライン継続・再更新を検証します。画像取得はモック判定で、実際の子どもの目の検出精度は自動試験の対象外です。

第三者資材は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) を参照してください。
